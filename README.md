# 💰 FreeMoney

PWA-приложение для учёта доходов и расходов. Работает **local-first**: данные
всегда хранятся на устройстве (IndexedDB) — мгновенно и офлайн, — а по желанию
синхронизируются с **вашей личной Google Таблицей**. Своего бэкенда у приложения
нет, оно целиком статическое и публикуется на GitHub Pages.

## Возможности

- **Список операций** с фильтрами (категория, тег, кошелёк, диапазон дат) и
  поиском по заметке или сумме; операции можно **редактировать и удалять**.
  Клик по категории открывает её операции.
- **Мультивалютные кошельки:** несколько кошельков, у каждого своя валюта.
  Базовая валюта задаётся в настройках — в ней считается общий капитал и сводная
  статистика по всем кошелькам. Курсы берутся из интернета и кэшируются (текущие —
  раз в день, исторические по дате — навсегда).
- **Операции в чужой валюте:** если платите не в валюте кошелька, приложение
  подставит конвертацию по курсу на дату операции (сумму списания можно поправить).
- **Переводы между кошельками** с указанием, сколько списано и сколько зачислено
  (учитывает разные валюты и комиссии).
- **Долги** — отдельный тип кошелька на контрагента. «Дал в долг» / «мне вернули»
  / «взял в долг» / «погасил» — это движение денег между рабочим и долговым
  кошельком, поэтому общий капитал не меняется, а часть средств становится
  «неволатильной». Знак баланса долгового кошелька показывает состояние: «+»
  вам должны, «−» должны вы (экран **🤝 Долг**).
- **Проценты на остаток** — у любого кошелька можно задать ставку (%). Кнопка
  «Начислить %» создаёт операцию дохода (на активе/вкладе) или расхода (на вашем
  долге) на величину `баланс × ставка`, с категорией «Проценты».
- **Статистика** — по каждому кошельку в его валюте и сводная в базовой валюте.
- **Управление тегами** — создание и удаление на отдельной странице; в операциях
  проставляются только уже существующие теги. Плюс **единая резервная копия** —
  весь набор данных в одном JSON-файле (экспорт/импорт).
- **Local-first хранение:** данные всегда на устройстве (IndexedDB) — правки
  применяются мгновенно и работают без интернета. Работает в любом браузере,
  включая iPhone; вход и настройка Google для базовой работы не нужны.
- **Опциональная синхронизация с Google Таблицей** (включается в настройках):
  данные держатся ещё и в вашей таблице и делятся между устройствами. Слияние —
  по правилу «последняя правка побеждает» с мягкими удалениями (tombstones);
  таблицу можно открывать и править руками. Синхронизация идёт в фоне и не
  блокирует интерфейс.
- **Экспорт и импорт CSV** (в настройках) — бэкап и перенос данных между
  устройствами; файлы открываются в Excel / Google Sheets.
- Вход через Google (OAuth в браузере, без сервера) — только при включении
  синхронизации. Таблица создаётся автоматически (или подключается существующая
  по ссылке).
- Учёт **расходов** и **доходов** по категориям, с заметками и датой.
- Категории трёх типов: только расход, только доход или оба; базовый набор
  создаётся сразу, можно добавлять свои.
- **Удаление категории = архивирование**: старые операции не ломаются, а из
  списков выбора категория пропадает. Архив можно посмотреть и восстановить.
- Страница статистики: баланс за месяц, разбивка расходов по категориям
  (круговая диаграмма) и динамика доход/расход по месяцам.
- Работает как устанавливаемое приложение (PWA): офлайн-оболочка, иконка на
  экране, полноэкранный режим.

## Как устроены данные

Источник правды — локальная база IndexedDB (`freemoney`, хранилища
`transactions`, `categories`, `wallets`, `tags`, `settings` и служебное
`_meta`). Каждая запись несёт метку изменения `updatedAt` (мс) для слияния и
флаг `deleted` (мягкое удаление — tombstone), чтобы удаление на одном устройстве
не «воскресало» при синхронизации с другого.

При включённой синхронизации те же данные лежат в Google Таблице (реплике) с
листами:

| Лист           | Колонки                                   |
| -------------- | ----------------------------------------- |
| `Transactions` | `id`, `datetime`, `type`, `amount`, `category`, `note`, `tags`, `wallet`, `currency`, `origAmount`, `origCurrency`, `transferId`, `rate`, `updatedAt`, `deleted` |
| `Categories`   | `name`, `kind`, `status`, `icon`, `id`, `order`, `updatedAt`, `deleted` |
| `Wallets`      | `id`, `name`, `currency`, `status`, `order`, `kind`, `rate`, `updatedAt`, `deleted` |
| `Tags`         | `name`, `updatedAt`, `deleted`            |
| `Settings`     | `key`, `value`, `updatedAt`               |

- `type` — `expense`, `income`, `transfer_in/out`, `adjust_in/out`, `interest_in/out`
- `kind` (категория) — `expense`, `income` или `both`
- `status` — `active` или `archived`
- `kind` (кошелёк) — `cash` (обычный) или `debt` (долговой, на контрагента)
- `rate` — ставка процентов, % (0 — не начисляем)
- `updatedAt` — метка изменения (мс) для слияния «последняя правка побеждает»
- `deleted` — tombstone (`1` — удалено)

Таблица обычная — её можно открыть в Google Sheets и править руками: изменения,
внесённые прямо в таблицу, синхронизация распознаёт (сравнением со снапшотом
прошлого захода) и подтягивает как свежие.

**Слияние.** Операции сопоставляются по `id`, кошельки — по `id`, теги — по
имени, настройки — по ключу, а **категории — по имени** (в приложении категория
адресуется именем; `id` категории — чисто локальный). Конфликты решаются по
`updatedAt`; данные при этом не теряются. Единственный возможный побочный эффект
при первом слиянии двух устройств, независимо заведённых до синхронизации, —
лишний пустой кошелёк «Основной» на втором устройстве (его можно заархивировать).

Настройка Google OAuth нужна **только для синхронизации** — без неё приложение
полностью работает локально.

### Формат CSV

- `freemoney-transactions.csv`: `id, date, type, amount, category, note, tags`
  (теги — через запятую внутри одной ячейки).
- `freemoney-categories.csv`: `name, kind, status, icon`.

При импорте дубликаты пропускаются: операции — по `id`, категории — по имени.

## Настройка Google OAuth (нужна только для режима Google Таблиц)

Без Client ID приложение не сможет авторизоваться. Делается один раз.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте
   проект (или выберите существующий).
2. **APIs & Services → Library** → включите:
   - **Google Sheets API**
   - **Google Drive API**
3. **APIs & Services → OAuth consent screen**:
   - Тип **External**, заполните название и e-mail.
   - Пока приложение в статусе *Testing*, добавьте свой Google-аккаунт в
     **Test users** (иначе вход не пройдёт).
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID**:
   - Тип приложения — **Web application**.
   - **Authorized JavaScript origins** добавьте адреса, откуда открывается
     приложение:
     - `http://localhost:5173` — для локальной разработки
     - `https://<ваш-логин>.github.io` — для GitHub Pages
   - Redirect URI для token flow не нужен.
5. Скопируйте **Client ID** вида `xxxx.apps.googleusercontent.com`.

### Куда вписать Client ID

- **Локально:** скопируйте `.env.example` в `.env` и подставьте значение:
  ```
  VITE_GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com
  ```
- **Для GitHub Pages:** в репозитории **Settings → Secrets and variables →
  Actions → New repository secret** создайте секрет с именем
  `VITE_GOOGLE_CLIENT_ID` и тем же значением. Сборка подхватит его автоматически.

> Client ID для web-приложения не является секретом в строгом смысле, но хранить
> его в секрете репозитория удобно и правильно.

## Публикация на GitHub Pages

Публикация идёт через ветку `gh-pages` (плагин `peaceiris/actions-gh-pages`),
чтобы на одном сайте Pages сосуществовали **два канала**:

- **prod** — `https://<логин>.github.io/<репозиторий>/` (собирается из `main`);
- **dev** — `https://<логин>.github.io/<репозиторий>/dev/` (собирается из `dev`).

Оба канала на **одном домене** (origin), поэтому вход через Google работает
одинаково и без правок в Google Cloud Console.

1. Создайте репозиторий и запушьте код в ветку `main`.
2. Добавьте секрет `VITE_GOOGLE_CLIENT_ID` (см. выше).
3. Push в `main` запускает `deploy.yml` → выкладывает prod в корень `gh-pages`.
   Push в `dev` запускает `deploy-dev.yml` → выкладывает dev в `gh-pages/dev/`.
   Оба workflow используют `keep_files: true`, поэтому не затирают чужой канал.
4. **Settings → Pages → Build and deployment → Source** выберите
   **Deploy from a branch**, ветка **`gh-pages`**, папка **`/ (root)`**.

> Порядок первого включения важен: сначала дайте `deploy.yml` отработать на
> `main` (он создаст ветку `gh-pages` с prod-версией в корне), и только потом
> переключайте источник Pages на ветку `gh-pages`. Иначе сайт будет пустым, пока
> ветка не наполнится.

### Dev-канал как отдельная PWA

`dev`-сборка имеет своё имя (`FreeMoney dev`) и путь `/dev/`, поэтому ставится
на телефон **отдельной иконкой** рядом с prod. На главном экране есть ссылка для
перехода между каналами, а в dev-версии — бейдж `DEV`.

> **Данные:** у каждого канала своя локальная база IndexedDB (разные origin —
> данные не пересекаются). Если на обоих каналах включить синхронизацию с **одной
> и той же** Google Таблицей, они сойдутся к общему состоянию через неё.

Приложение будет доступно по адресу
`https://<ваш-логин>.github.io/<имя-репозитория>/`.

> **Важно:** `base` в `vite.config.js` и `BASE_PATH` в workflow вычисляются из
> имени репозитория автоматически. Если публикуете под кастомным доменом или в
> корне (`<логин>.github.io`), задайте `BASE_PATH=/` при сборке.

## Мобильное приложение (Capacitor)

Приложение можно собрать как нативное для Android/iOS через
[Capacitor](https://capacitorjs.com/). Веб-код переиспользуется как есть.

Сборка веб-части для обёртки использует `base: '/'` (не `/freemoney/`):

```bash
npm run cap:sync      # сборка (build:app) + копирование в нативный проект
npm run cap:android   # открыть проект в Android Studio (там же собирается APK)
```

Для Android нужен Android Studio (JDK + SDK), для iOS — Mac с Xcode
(`npx cap add ios` создаст iOS-проект). Публикация в сторы требует
аккаунтов Google Play / Apple Developer.

В нативной сборке появляется третий способ хранения — **«Файлы на устройстве
(.csv)»**: данные лежат в `.csv` файлах в папке «Документы» устройства
(через `@capacitor/filesystem`). В обычном браузере этот режим скрыт.

## Стек

- **React + Vite** — фронтенд и сборка
- **react-router-dom** (HashRouter — работает на статике GitHub Pages без
  серверных редиректов)
- **recharts** — графики (грузится отдельным чанком только на странице
  статистики)
- **vite-plugin-pwa** — манифест и service worker
- **Google Sheets API + Drive API** — хранилище (scope `drive.file`, доступ
  только к файлам, созданным приложением)

## Структура проекта

```
src/
  auth/googleAuth.js     — OAuth через Google Identity Services
  api/sheets.js          — низкоуровневые вызовы Sheets/Drive REST API
  api/store.js           — модель данных (транзакции, категории)
  context/AppContext.jsx — состояние приложения и действия
  pages/                 — экраны (Home, AddTransaction, Categories, Stats, Gate)
  components/NavBar.jsx   — нижняя навигация
  utils/format.js        — форматирование денег и дат
  config.js              — Client ID, scope, константы
```
